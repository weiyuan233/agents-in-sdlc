GitHub Pages にデプロイして、Space Quiz を誰もがアクセスできるようにしましょう。Copilot はワークフローを準備し、デプロイを案内できますが、変更をレビューし、サイトが公開されたことを確認するのは開発者の役割です。

このレッスンでは、次のことを行います。

- Copilot に GitHub Pages のデプロイを設定するよう依頼します。
- マージする前に、ワークフローとプルリクエストをレビューします。
- デプロイの進行状況を確認し、公開されたサイトを検証します。

## シナリオ

Space Quiz はすでに GitHub リポジトリにありますが、利用者が手軽に試せる場所が必要です。単一ファイルのサイトを GitHub Pages で公開すると、サーバーやランタイム依存関係を追加せずに、公開先 Uniform Resource Locator (URL) からアクセスできるようになります。

## Copilot にデプロイの準備を依頼する

> [!WARNING]
> プルリクエストを作成すると、コードが commit および push されることがあります。プロンプトを送る前に、承認設定と送信先リポジトリを確認してください。**Approve all** が有効な場合、別途確認を求められないことがあります。

`space-quiz` の Copilot app セッションで、次のプロンプトを送信します。

```plaintext
このリポジトリで GitHub Pages にデプロイする準備をしてください。必要であれば Web サイトをビルドし、変更が既定のブランチに反映された後に GitHub Pages へデプロイする GitHub Actions ワークフローを作成してください。README がまだない場合は、アプリとローカルでの実行方法を説明する README を追加してください。これらの変更でプルリクエストを作成し、そのリンクと、必要な Pages の設定または権限を報告してください。マージ、自動マージの有効化、Pages の設定変更、デプロイは行わないでください。停止して、私のレビューを待ってください。
```

## ワークフローとプルリクエストをレビューする

マージを許可する前に、README の追加条件とワークフローの動作を確認し、必要なチェックが成功していることを確かめます。

1. README は、リポジトリにまだ存在しない場合にのみ追加されていることを確認します。
2. ビルドとデプロイの手順、トリガー、権限を含め、プルリクエストの変更をレビューします。
3. ワークフローが、未マージのプルリクエストではなく既定のブランチからデプロイすることを確認します。
4. 修正が必要な場合は依頼し、更新後の差分をレビューします。マージを許可する前に、必須のプルリクエストチェックが成功するまで待ちます。

## マージとデプロイを許可する

> [!WARNING]
> 次のプロンプトを送ると、レビュー済みのプルリクエストのマージ、リポジトリの Pages 設定変更、サイトの公開をエージェントに許可します。レビューを完了し、リポジトリとプルリクエストを確認してから送信してください。承認設定によっては、追加の確認なしにこれらの操作が実行されることがあります。

レビューしたプルリクエストの番号を `<PR_NUMBER>` に入れ替え、別のプロンプトとして送信します。

```plaintext
このリポジトリのプルリクエスト <PR_NUMBER> をレビューし、マージとデプロイを許可します。GitHub Actions を使う GitHub Pages を有効にし、必須チェックの成功後にそのプルリクエストだけをマージし、デプロイが成功するまで監視してください。公開された Web サイトの最終 URL を報告してください。Pages を有効にする権限、またはマージする権限がない場合は、私が承認または実行する必要がある内容を正確に伝えてください。サイトが公開されるまでは、成功したと報告しないでください。
```

## デプロイを確認する

マージ後は、GitHub Actions の実行結果と公開サイトの両方を確認し、デプロイが完了したことを確かめます。

1. GitHub Actions のデプロイ実行が成功するまで確認します。
2. 報告された URL を開き、Space Quiz が表示されることを確認します。

エージェントが Pages の有効化やプルリクエストのマージを実行できない場合は、エージェントが示す具体的な手順に従います。デプロイが成功し、公開サイトが読み込まれるまでは、作業を完了したとみなさないでください。
